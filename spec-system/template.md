# 规范模板

## 一、概述

本文档定义"可复用的AI辅助开发规范体系"中每个规范的标准模板，确保规范的一致性和可维护性。

---

## 二、模板结构

### 2.1 必填字段

| 字段 | 描述 | 说明 |
|------|------|------|
| **编号** | 规范的唯一标识符 | 格式：C01/B01/S01 |
| **名称** | 规范的简短名称 | 简洁明了，不超过20字 |
| **描述** | 规范的详细描述 | 说明规范的内容和目的 |
| **层次** | 规范所属层次 | L1核心/L2最佳实践/L3场景 |
| **领域** | 规范所属领域 | 架构/编码/流程/测试/部署/文档 |
| **来源** | 规范的来源项目 | CSO-FORCS/WarehouseMS/共有 |
| **验证标准** | 规范的验证标准 | 可执行的检查项 |
| **可复用性** | 规范的可复用性评估 | 高/中/低 |

### 2.2 可选字段

| 字段 | 描述 | 说明 |
|------|------|------|
| **适用场景** | 规范适用的具体场景 | 仅L3场景规范需要 |
| **实现方式** | 规范的实现方式 | 代码示例或配置示例 |
| **验证命令** | 验证规范的命令 | 自动化检查命令 |
| **依赖规范** | 规范依赖的其他规范 | 规范关系 |
| **组合规范** | 可以组合使用的规范 | 规范组合 |
| **演进历史** | 规范的演进历史 | 版本变更记录 |
| **参考文档** | 相关参考文档 | 链接或文件路径 |

## 三、模板示例

### 3.1 核心规范模板（L1）

```markdown
# C01：分层架构

## 基本信息

| 字段 | 内容 |
|------|------|
| **编号** | C01 |
| **名称** | 分层架构 |
| **描述** | 严格分层，单向依赖，禁止反向引用 |
| **层次** | L1核心规范层 |
| **领域** | 架构 |
| **来源** | 共有 |
| **可复用性** | 高 |

## 规范内容

### 目标
确保代码组织清晰，依赖方向明确，便于维护和扩展。

### 规则
1. 依赖方向单向（上层依赖下层）
2. 禁止反向引用（下层不能引用上层）
3. 通过接口解耦

### 实现方式
```
Models <- DAL <- BLL <- Api <- App
```

## 验证标准

| 检查项 | 验证方法 | 优先级 |
|--------|----------|--------|
| 依赖方向正确 | 检查ProjectReference方向 | 红线 |
| 无反向引用 | 下层项目不引用上层项目 | 红线 |
| 接口解耦 | 通过接口而非具体类依赖 | 最佳实践 |

## 验证命令

```bash
# 检查依赖方向
dotnet build 2>&1 | grep "circular dependency"

# 检查ProjectReference
grep -r "ProjectReference" src/ --include="*.csproj"
```

## 验证结果

- ✅ 通过：依赖方向正确，无反向引用
- ❌ 失败：存在反向引用或循环依赖

## 依赖规范

无

## 组合规范

- B01：Repository模式
- B02：Unit of Work
- S01：硬件抽象层
- S02：双子系统架构
- S03：三大系统边界

## 参考文档

- [规范体系结构](structure.md)
- [验证标准](verification-standards.md)
```

### 3.2 最佳实践模板（L2）

```markdown
# B01：Repository模式

## 基本信息

| 字段 | 内容 |
|------|------|
| **编号** | B01 |
| **名称** | Repository模式 |
| **描述** | 数据访问层抽象，封装数据库操作 |
| **层次** | L2最佳实践层 |
| **领域** | 架构 |
| **来源** | 共有 |
| **可复用性** | 高 |

## 规范内容

### 目标
封装数据访问逻辑，提供统一的数据访问接口。

### 规则
1. 接口+实现分离
2. 封装CRUD操作
3. 不包含业务逻辑
4. 通过DI注册

### 实现方式

```csharp
// 接口
public interface IGoodsRepository
{
    Task<Goods?> GetByIdAsync(int id);
    Task<List<Goods>> GetAllAsync();
    Task AddAsync(Goods entity);
    Task UpdateAsync(Goods entity);
    Task DeleteAsync(int id);
}

// 实现
public class GoodsRepository : IGoodsRepository
{
    private readonly AppDbContext _context;
    
    public async Task<Goods?> GetByIdAsync(int id)
        => await _context.Goods.FindAsync(id);
    
    // 其他方法实现
}
```

## 验证标准

| 检查项 | 验证方法 | 优先级 |
|--------|----------|--------|
| 接口+实现分离 | 检查接口和实现类 | 红线 |
| 封装CRUD操作 | 检查方法定义 | 最佳实践 |
| 不包含业务逻辑 | 代码审查 | 最佳实践 |
| 通过DI注册 | 检查DI配置 | 红线 |

## 验证命令

```bash
# 检查Repository接口
grep -r "IRepository" src/ --include="*.cs" | head -10

# 检查DI注册
grep -r "AddScoped.*Repository" src/ --include="*.cs"
```

## 验证结果

- ✅ 通过：接口+实现分离，封装CRUD
- ❌ 失败：缺少接口或实现，包含业务逻辑

## 依赖规范

- C01：分层架构

## 组合规范

- B02：Unit of Work

## 参考文档

- [规范体系结构](structure.md)
- [验证标准](verification-standards.md)
```

### 3.3 场景规范模板（L3）

```markdown
# S01：硬件抽象层

## 基本信息

| 字段 | 内容 |
|------|------|
| **编号** | S01 |
| **名称** | 硬件抽象层 |
| **描述** | 定义硬件接口，Mock实现支持离线调试 |
| **层次** | L3场景规范层 |
| **领域** | 架构 |
| **来源** | CSO-FORCS |
| **可复用性** | 中高 |

## 适用场景

- 物联网/工业应用
- 需要硬件设备交互
- 需要离线调试能力

## 规范内容

### 目标
抽象硬件设备接口，支持离线调试和测试。

### 规则
1. 定义清晰的硬件接口
2. 提供Mock实现
3. 维护实现状态矩阵
4. 32位依赖通过独立进程隔离

### 实现方式

```csharp
// 接口定义
public interface ICardReader
{
    Task<string?> ReadCardAsync(CancellationToken ct = default);
}

// Mock实现
public class DisabledCardReader : ICardReader
{
    public Task<string?> ReadCardAsync(CancellationToken ct = default)
        => Task.FromResult<string?>(null);
}

// 真实实现
public class HttpCardReaderClient : ICardReader
{
    // HTTP调用微服务
}
```

## 验证标准

| 检查项 | 验证方法 | 优先级 |
|--------|----------|--------|
| 接口定义清晰 | 检查接口定义 | 红线 |
| Mock实现存在 | 检查Mock类 | 红线 |
| 实现状态矩阵维护 | 检查文档 | 最佳实践 |
| 32位依赖隔离 | 检查微服务 | 最佳实践 |

## 验证命令

```bash
# 检查HAL接口
grep -r "I.*Reader\|I.*Sensor\|I.*Scanner" src/ --include="*.cs"

# 检查Mock实现
grep -r "Disabled.*\|Mock.*" src/ --include="*.cs"
```

## 验证结果

- ✅ 通过：接口定义清晰，Mock实现存在
- ❌ 失败：缺少接口或Mock实现

## 依赖规范

- C01：分层架构

## 组合规范

- S11：一键跨平台部署
- S12：升级保护与回滚

## 参考文档

- [规范体系结构](structure.md)
- [验证标准](verification-standards.md)
```

## 四、模板使用指南

### 4.1 创建新规范

1. **选择模板**：根据规范层次选择对应模板
2. **填写必填字段**：确保所有必填字段都已填写
3. **填写可选字段**：根据需要填写可选字段
4. **定义验证标准**：确保验证标准可执行
5. **编写验证命令**：提供自动化检查命令
6. **定义依赖关系**：明确规范依赖
7. **定义组合关系**：明确规范组合

### 4.2 更新现有规范

1. **检查变更**：确认规范需要更新
2. **更新内容**：更新规范内容
3. **更新验证标准**：确保验证标准仍然有效
4. **更新版本**：更新演进历史
5. **通知相关方**：通知使用该规范的项目

### 4.3 规范评审

1. **完整性检查**：确保所有必填字段都已填写
2. **一致性检查**：确保规范与其他规范一致
3. **可执行性检查**：确保验证标准可执行
4. **可复用性评估**：评估规范的可复用性

## 五、模板字段说明

### 5.1 编号规则

- **L1核心规范**：C01-C99
- **L2最佳实践**：B01-B99
- **L3场景规范**：S01-S99

### 5.2 层次说明

- **L1核心规范层**：必须遵守的红线规范
- **L2最佳实践层**：建议遵守的推荐规范
- **L3场景规范层**：按需选择的特定场景规范

### 5.3 领域说明

- **架构**：系统架构、模块划分、依赖关系
- **编码**：代码风格、命名约定、错误处理
- **流程**：开发流程、代码审查、变更管理
- **测试**：测试策略、测试覆盖、测试工具
- **部署**：部署流程、环境管理、回滚机制
- **文档**：文档规范、注释标准、知识管理

### 5.4 可复用性评估

- **高**：适用于大多数项目
- **中**：适用于特定类型项目
- **低**：适用于特定场景
