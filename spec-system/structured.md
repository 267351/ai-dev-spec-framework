# 规范体系结构化文档

## 一、概述

本文档是"可复用的AI辅助开发规范体系"的核心文档，将45个规范组织为层次化、可查询的结构化体系。

---

## 二、体系架构

### 2.1 三层架构

```
┌─────────────────────────────────────────────────────────────┐
│                    L1: 核心规范层                            │
│              （必须遵守，红线规范）                           │
├─────────────────────────────────────────────────────────────┤
│                    L2: 最佳实践层                            │
│              （建议遵守，推荐规范）                           │
├─────────────────────────────────────────────────────────────┤
│                    L3: 场景规范层                            │
│              （按需选择，特定场景）                           │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 各层职责

| 层次 | 职责 | 规范类型 | 验证方式 |
|------|------|----------|----------|
| **L1: 核心规范层** | 定义必须遵守的红线规范 | 架构铁律、命名约定、安全规范 | 自动化检查+人工审查 |
| **L2: 最佳实践层** | 定义建议遵守的推荐规范 | 设计模式、编码风格、测试规范 | 代码审查+工具检查 |
| **L3: 场景规范层** | 定义特定场景的规范 | 硬件抽象、实时通信、部署规范 | 场景匹配+专家评审 |

## 六、验证体系

### 6.1 验证层次

| 层次 | 验证方式 | 工具 | 频率 |
|------|----------|------|------|
| **自动化检查** | 静态分析、编译检查 | Roslyn Analyzer, dotnet build | 每次提交 |
| **工具检查** | 代码风格、命名约定 | EditorConfig, StyleCop | 每次提交 |
| **代码审查** | 逻辑正确性、规范遵循 | PR审查 | 每次合并 |
| **专家评审** | 架构设计、场景适用性 | 人工评审 | 重大变更 |

### 6.2 验证标准格式

```markdown
## 规范名称

### 验证标准
1. [检查项1] - [验证方法]
2. [检查项2] - [验证方法]
3. [检查项3] - [验证方法]

### 验证命令
```bash
# 自动化检查
dotnet build
dotnet test

# 工具检查
dotnet format --verify-no-changes
```

### 验证结果
- ✅ 通过：所有检查项都满足
- ❌ 失败：有检查项不满足，需要修复
```

## 七、扩展机制

### 7.1 添加新规范

**流程**：
1. 识别需求（新场景/新问题）
2. 分析现有规范是否适用
3. 设计新规范
4. 定义验证标准
5. 更新规范索引
6. 更新规范体系结构

**规范模板**：
```markdown
## 规范名称

### 描述
[简要描述规范的内容和目的]

### 适用场景
[描述规范适用的场景]

### 实现方式
[提供实现示例]

### 验证标准
1. [检查项1]
2. [检查项2]
3. [检查项3]

### 可复用性
[评估规范的可复用性]
```

### 7.2 规范演进

**演进触发条件**：
- 新技术出现
- 新最佳实践验证
- 项目需求变化
- 反馈收集

**演进流程**：
1. 收集反馈
2. 评估影响
3. 设计变更
4. 更新规范
5. 通知相关方

## 八、使用指南

### 8.1 新项目启动

1. **选择核心规范**：必须遵守L1核心规范
2. **选择最佳实践**：根据项目需求选择L2最佳实践
3. **选择场景规范**：根据项目场景选择L3场景规范
4. **定制规范**：根据项目特点定制规范

### 8.2 现有项目改进

1. **评估现状**：检查现有项目对规范的遵循情况
2. **识别差距**：识别与规范的差距
3. **制定计划**：制定改进计划
4. **逐步实施**：逐步实施改进

### 8.3 AI辅助开发

1. **加载规范**：将规范加载到AI上下文
2. **执行检查**：AI检查代码是否符合规范
3. **提供建议**：AI提供改进建议
4. **记录偏差**：记录并处理偏差
