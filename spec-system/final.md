# 可复用的AI辅助开发规范体系

## 一、概述

本文档是"可复用的AI辅助开发规范体系"的最终文档，汇总了从CSO-FORCS和WarehouseMS两个项目中提取的所有规范，包括规范体系、验证标准、使用指南。

---

## 二、项目背景

### 2.1 研究背景

当前AI辅助开发工具（如Copilot、Cursor等）在编码过程中存在"乱写代码"的问题，缺乏统一的规范约束。本项目旨在从实际项目中提炼出一套可复用的开发规范，使AI在协助开发时有章可循，确保代码质量和一致性。

### 2.2 研究方法

1. **数据收集**：对两个实际项目（CSO-FORCS和WarehouseMS）进行深度分析
2. **模式提取**：从两个项目的共同点和差异点中提取规范
3. **体系化**：将规范组织为结构化体系
4. **验证**：在实际项目中验证规范的有效性

### 2.3 研究成果

- **规范数量**：45个规范
- **规范层次**：3层（核心规范/最佳实践/场景规范）
- **规范领域**：6个（架构/编码/流程/测试/部署/文档）
- **验证结果**：21个完全遵循，5个部分遵循，4个未遵循，2个不适用

## 三、规范体系架构

### 3.1 三层架构

```
┌─────────────────────────────────────────────────────────────┐
│                    L1: 核心规范层                            │
│              （必须遵守，红线规范）                           │
├─────────────────────────────────────────────────────────────┤
│                    L2: 最佳实践层                            │
│              （建议遵守，推荐规范）                           │
├─────────────────────────────────────────────────────────────┤
│                    L3: 场景规范层                            │
│              （按需选择，特定场景）                           │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 各层职责

| 层次 | 职责 | 规范类型 | 验证方式 |
|------|------|----------|----------|
| **L1: 核心规范层** | 定义必须遵守的红线规范 | 架构铁律、命名约定、安全规范 | 自动化检查+人工审查 |
| **L2: 最佳实践层** | 定义建议遵守的推荐规范 | 设计模式、编码风格、测试规范 | 代码审查+工具检查 |
| **L3: 场景规范层** | 定义特定场景的规范 | 硬件抽象、实时通信、部署规范 | 场景匹配+专家评审 |

### 3.3 规范分类

| 领域 | L1核心规范 | L2最佳实践 | L3场景规范 |
|------|------------|------------|------------|
| **架构** | 分层架构、依赖方向 | Repository模式、Unit of Work | HAL层、双子系统、微服务 |
| **编码** | 命名约定、异步编程 | 结构化日志、错误处理 | Result模式、API异常处理 |
| **流程** | Spec.md体系、Conventional Commits | 代码审查、文档管理 | AGENTS.md索引、偏差检测 |
| **测试** | 单元测试 | 测试覆盖、测试基类 | SQLite内存测试、集成测试 |
| **部署** | 版本管理 | 部署脚本、回滚机制 | 一键跨平台、Kiosk模式 |
| **文档** | XML文档注释 | 架构文档、变更日志 | 业务规则引用、坑点记录 |

## 九、使用指南

### 9.1 新项目启动

1. **选择核心规范**：必须遵守L1核心规范（C01-C07）
2. **选择最佳实践**：根据项目需求选择L2最佳实践（B01-B10）
3. **选择场景规范**：根据项目场景选择L3场景规范（S01-S15）
4. **定制规范**：根据项目特点定制规范

### 9.2 现有项目改进

1. **评估现状**：检查现有项目对规范的遵循情况
2. **识别差距**：识别与规范的差距
3. **制定计划**：制定改进计划
4. **逐步实施**：逐步实施改进

### 9.3 AI辅助开发

1. **加载规范**：将规范加载到AI上下文
2. **执行检查**：AI检查代码是否符合规范
3. **提供建议**：AI提供改进建议
4. **记录偏差**：记录并处理偏差
