## 4.2 创作逻辑提取结果

### 4.2.1 架构模式分析

**共同架构模式**：

两个项目都采用了分层架构模式，确保代码组织清晰，依赖方向明确：

| 项目 | 分层结构 | 依赖方向 |
|------|----------|----------|
| CSO-FORCS | Models <- DAL <- BLL <- Api <- App | 单向向下 |
| WarehouseMS | Shared <- Infrastructure <- Core <- Web | 单向向下 |

**共同特征**：
- 每层有明确职责
- 依赖方向单向（上层依赖下层）
- 禁止反向引用（下层不能引用上层）
- 通过接口解耦

**差异架构模式**：

| 维度 | CSO-FORCS | WarehouseMS |
|------|-----------|-------------|
| 整体架构 | 模块化单体 + 1个微服务 | 模块化单体（纯单体） |
| 子系统 | 双子系统（独立API+前端） | 3个逻辑子系统（共享层） |
| 通信机制 | REST API + SignalR | Blazor Server SignalR |
| 硬件抽象 | HAL层（接口+Mock） | 无 |

### 4.2.2 代码组织规范

**共同代码组织规范**：

| 规范类型 | 规范内容 | 验证标准 |
|----------|----------|----------|
| 命名约定 | PascalCase/camelCase/_前缀/I前缀 | 静态分析通过 |
| 文件组织 | 一层一个文件，命名空间匹配目录 | 文件检查通过 |
| 异步编程 | Async后缀，无async void | 静态分析通过 |
| 结构化日志 | Serilog {Placeholder}语法 | 日志格式正确 |

**差异代码组织规范**：

| 规范类型 | CSO-FORCS | WarehouseMS |
|----------|-----------|-------------|
| 错误处理 | 异常传播模式 | Result模式 |
| 日志系统 | 双日志系统 | 统一ILogger<T> |
| 知识管理 | 坑编号系统 | 业务规则引用 |

### 4.2.3 命名规范提取

两个项目都遵循Microsoft C#标准命名约定：

| 元素 | 约定 | 示例 |
|------|------|------|
| Namespace | PascalCase | `LimitedSpaceForeignObject.BLL.Services` |
| Class | PascalCase | `GoodsService` |
| Interface | I前缀+PascalCase | `IGoodsService` |
| Method | PascalCase | `GetByIdAsync` |
| Property | PascalCase | `GoodsName` |
| Private Field | _camelCase | `_goodsRepository` |
| Parameter | camelCase | `goodsCode` |
| Local Variable | camelCase | `existingSession` |
| Async Method | Async后缀 | `GetByIdAsync` |

### 4.3.2 代码审查流程

**共同特点**：
- 无正式PR流程
- 依赖.spec.md文件进行知识传承
- 通过自动化检查确保质量

**Spec.md约定文件体系**：
- 两个项目都有100+个.spec.md文件
- 记录：文件用途、踩过的坑、禁止修改的内容
- 修改代码前必须检查spec.md
- 修改后主动询问是否更新spec.md

**Spec.md模板**：
```markdown
## 文件用途
[简要描述文件的用途和职责]

## 踩过的坑
[记录开发过程中遇到的问题和解决方案]

## 禁止修改的内容
[列出不能修改的内容和原因]

## 技术规范
[描述技术实现规范]

## 允许的操作
[列出允许的操作]

## 当前状态
[描述文件当前状态]

## 维护提示
[提供维护建议]
```

### 4.3.3 部署流程规范

**CSO-FORCS部署流程**：
- 一键跨平台部署（deploy.sh/deploy.ps1）
- 升级保护与回滚（upgrade.sh）
- Launcher进程编排
- Kiosk双屏模式

**WarehouseMS部署流程**：
- 手动部署（dotnet run）
- 无部署脚本
- 无回滚机制

**部署规范对比**：
| 规范 | CSO-FORCS | WarehouseMS |
|------|-----------|-------------|
| 部署脚本 | 2600+行 | 无 |
| 跨平台支持 | Linux/Windows | 无 |
| 回滚机制 | 自动备份+回滚 | 无 |
| 健康检查 | 启动时检查 | 无 |
