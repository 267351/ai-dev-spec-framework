# 数据收集阶段执行计划

## 一、目标

完成两个项目（CSO-FORCS和WarehouseMS）的深度数据收集，产出原始数据和模式识别报告，为后续模式提取阶段奠定基础。

## 二、项目概况

| 项目 | 文件数量 | 技术栈 | 特点 |
|------|----------|--------|------|
| CSO-FORCS | 1489个文件 | C# 13, .NET 10, Blazor SSR + WASM, SQLite + EF Core 10, SignalR | 双子系统架构（有限空间作业系统 + 库房管理系统），工业安全管理系统 |
| WarehouseMS | 682个文件 | C# 13, .NET 10, Blazor Web App (InteractiveAuto), MudBlazor 8.x, SQLite + EF Core 10 | 工业研磨物资全链路管理系统，聚焦磨锉工工作量双维度评估 |

## 三、执行步骤

### 阶段1：项目基本信息收集（模板1）

**目标**：收集两个项目的基本信息，建立项目档案。

**步骤**：
1. 分析CSO-FORCS项目基本信息
   - 项目类型：Web应用（工业安全管理系统）
   - 技术栈：C# 13, .NET 10, Blazor SSR + WASM, SQLite + EF Core 10, SignalR
   - 项目规模：1489个文件
   - 团队规模：从提交历史推断
   - 项目周期：从提交历史推断
   - 开源/闭源：内部项目

2. 分析WarehouseMS项目基本信息
   - 项目类型：Web应用（工业研磨物资管理系统）
   - 技术栈：C# 13, .NET 10, Blazor Web App (InteractiveAuto), MudBlazor 8.x, SQLite + EF Core 10
   - 项目规模：682个文件
   - 团队规模：从提交历史推断
   - 项目周期：从提交历史推断
   - 开源/闭源：内部项目

**验收标准**：完成模板1的填写，产出两个项目的基本信息档案。

### 阶段2：架构分析（模板2）

**目标**：分析两个项目的架构设计，提取架构模式。

**步骤**：
1. 分析CSO-FORCS架构
   - 整体架构：双子系统架构（有限空间作业系统 + 库房管理系统）
   - 分层结构：表现层/业务层/数据层/硬件抽象层
   - 模块划分：22个实体、15个枚举、12个DTO、19个仓储、29个服务
   - 依赖关系：模块间依赖、外部依赖
   - 通信机制：RESTful API + SignalR实时通信

2. 分析WarehouseMS架构
   - 整体架构：单体应用架构
   - 分层结构：Shared/Infrastructure/Core/Web四层架构
   - 模块划分：18个业务服务
   - 依赖方向：Shared ← Infrastructure ← Core ← Web
   - 通信机制：Blazor Server + WebAssembly混合模式

**验收标准**：完成模板2的填写，产出两个项目的架构分析报告。

2. 分析WarehouseMS代码规范
   - 命名规范：变量、函数、类、接口的命名风格

   - 错误处理：异常捕获、错误传播、错误日志

   - 注释规范：注释类型、内容、频率

**验收标准**：完成模板3的填写，产出两个项目的代码规范分析报告。

## 四、并行执行机会

1. **阶段1-6**中，两个项目的分析可以并行进行
2. **阶段7**依赖于阶段1-6的完成，不能并行

## 五、依赖关系

- 阶段1-6相互独立，可以并行执行
- 阶段7依赖于阶段1-6的完成
- 所有阶段都依赖于项目基本信息的收集（阶段1）

## 六、验收标准

1. 完成所有模板（1-7）的填写
2. 产出完整的数据收集报告
3. 所有分析都有明确的代码证据支持
4. 提取的规范具有可验证性

## 七、风险点

1. **项目规模风险**：CSO-FORCS项目规模较大（1489个文件），可能需要更多时间
2. **技术栈差异风险**：两个项目技术栈相似但存在差异，需要仔细对比
3. **文档完整性风险**：项目文档可能不完整，需要从代码中提取更多信息
4. **时间风险**：数据收集阶段可能需要较长时间，需要合理分配

## 八、产出物

1. 项目基本信息档案（模板1）
2. 架构分析报告（模板2）
3. 代码规范分析报告（模板3）
4. 工作流程分析报告（模板4）
5. 设计模式分析报告（模板5）
6. Skills清单（模板6）
7. 横向对比分析报告（模板7）
8. 完整的数据收集总结报告

## 九、执行策略

1. **并行分析**：同时启动两个项目的分析任务
2. **模板驱动**：严格按照7个标准化模板进行分析
3. **证据导向**：每个结论都需要有代码证据支持
4. **渐进式**：先从核心规范开始，再逐步扩展到细节规范
